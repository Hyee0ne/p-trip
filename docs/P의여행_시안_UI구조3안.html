UI 구조 3안

이번엔 색을 일부러 고정했습니다. 세 안의 배경·글자·강조색이 전부 같습니다 — 다른 건 화면을 어떤 구조로 조립하느냐뿐이라 구조만 비교하시면 됩니다. 각 안은 mobbin에서 우리 기능과 구조가 같은 앱을 찾아 가져왔습니다.

이번에 반영한 것

여행기 명조 → 고딕. 앱 전체가 Pretendard 하나로 통일됐습니다.
컨셉 = UI 구조. 지난번은 색만 달랐습니다. 이번엔 지도를 쓸지, 선을 쓸지, 전면 카드를 쓸지가 갈립니다 — 화면 조립 방식 자체가 다릅니다.

B
여정 타임라인 — 길을 세로 선으로 편다

Transit의 여정 상세가 우리 구조와 정확히 같습니다. 색면 블록은 타는 노선, 점선 커넥터는 "걸어서 2분". 우리로 치면 블록 = 국도 구간, 커넥터 = 국도에서 4분입니다.
가장 큰 이점은 계획과 기록이 같은 형식이라는 것 — 코스 상세(예고편)와 여행기(다시보기)가 같은 선 위에서 하나는 비어 있고 하나는 채워져 있습니다.

C
전면 카드 — 한 번에 하나만 크게

발견 하나가 화면을 통째로 차지한다. 사진이 크고 버튼이 원형으로 크며 스와이프로 넘긴다. 데이팅 앱이 이 패턴을 쓰는 이유는 한 손, 한 눈, 한 번의 결정에 최적이기 때문 — 운전 중 조작 조건과 정확히 같다. 액션 3종(들르기/찜/넘기기)이 원형 버튼 3개에 그대로 맞는다.

권고
B를 뼈대로, C를 레이더에

셋 중 하나만 고르면 각각의 약점이 그대로 남습니다. 실제로는 화면 성격에 따라 나누는 게 맞습니다.

B(여정 타임라인)를 앱의 기본 문법으로 — 홈·코스 상세·여행기. 계획과 기록이 같은 선을 쓰는 이점이 크고, 지도 플러그인 리스크를 피합니다.
C(전면 카드)를 레이더 발견 카드에만 — 운전 중이라 정보 밀도보다 터치 안전이 우선입니다.
A(지도)는 거점 찍기(CO-06)와 코스 지도 미리보기에서만 — 위치를 골라야 하는 화면에만 지도를 씁니다.
