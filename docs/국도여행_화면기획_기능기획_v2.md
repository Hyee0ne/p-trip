# P의 여행 — 화면기획 · 기능기획 v2

서비스명: **P의 여행** / 핵심 카피: **"지나치기엔 아까운 것들이, 길마다 있어요."**
컨셉: "조수석에 탄 로컬 친구" — 길안내는 네비에 맡기고, 우리는 경로 위의 발견을 책임진다
메인: 국도 위의 우연한 발견 — 발견이 본편, 코스는 예고편, 여행기는 다시보기. 숙소·체류는 서비스 영역이 아님 (거점은 '위치 입력값'일 뿐)

**비내비(非-Navi) 3원칙 — 모든 화면·문구가 이걸 따른다**
1. **경로를 소유하지 않는다** — 길안내·경로 재탐색·ETA를 절대 제공하지 않음. 이동은 외부 네비의 일.
2. **이탈은 실패가 아니다** — 목적지가 바뀌거나 코스를 벗어나도 "이탈" 알림 없음. 그저 새 주변 기준으로 발견을 갱신할 뿐. 코스는 추천 재료지 지켜야 할 약속이 아님.
3. **재촉하지 않는다** — 카운트다운·"빨리 결정하세요" 류 UX 금지. 지나치면 찜으로 남아 다음 기회가 됨. 우리는 목적지가 아니라 '지금 주변'에 스며들게 돕는다.

## 1. 서비스 구조 (IA)

```
P의 여행
├── 온보딩 / 로그인
├── [탭1] 발견 — 출발 전
│   ├── 홈 (발견 큐레이션 3축)
│   ├── 국도 선택 (번호로 탐색 — 7번, 44번…)
│   ├── 코스 상세 (경로 지도 + 발견 포인트)
│   ├── 거점 설정 (오늘 밤 잘 곳 — 입력·선택, 예약은 외부)
│   ├── 마을 상세
│   ├── 스팟 상세 (밥집/뷰포인트/문화시설/숙소 — 전부 동급 스팟)
│   └── 내 코스 만들기 (찜 기반)
├── [탭2] 레이더 — 이동 중
│   ├── 레이더 모드 (현재 위치 반경 + 근접 발견 카드)
│   ├── 근접 알림 (백그라운드 푸시/오디오)
│   ├── 솔로 모드 (음성 응답·자동 찜)
│   └── 동승자 브라우징 모드
├── [탭3] 마이
│   ├── 찜 & 스쳐간 발견
│   ├── 자동 여행기 (말미에 "하루 더?" 한 줄 제안 포함)
│   └── 설정
└── 공통: 외부 네비 딥링크, 공유, 알림
```

## 3. 핵심 유저 플로우

```
[출발 전] 홈 → 코스 상세 → 스팟 몇 개 찜 → 거점 위치 입력(선택사항) → "이 코스로 출발"
[이동 중] 레이더 모드 → 근접 카드 "근처에 ○○마을" → 들르기(네비 딥링크) — 잘 곳이 정해져 있어 낮의 즉흥이 과감해짐
[도착 후] 여행기 자동 생성 → 공유 → 말미 한 줄: "이 동네가 좋았다면, 하루 더?"
```

진입로 3개 (도착점은 모두 레이더):
① 길에서 시작 — 홈 큐레이션의 코스를 고르거나, 국도 번호(CO-07)를 직접 고름
② 거점에서 시작 — 숙소 먼저 예약한 유저가 위치만 찍으면 "고속도로 대신 국도" 제안
③ 그냥 시작 — 계획 없이 레이더만 켜고 달림 / 백그라운드 근접 알림으로 앱 진입
(③이 예능적 "우연한 발견"의 핵심 경험)

## 4. 발견 알고리즘 정의 (차별성의 근거) — 프레임: **설계된 우연**

즉흥이 어떻게 좋은 경험을 보장하는가에 대한 답. 계획이 사라지는 게 아니라 계획 노동(후기 검색·동선·영업시간 확인)이 시스템으로 이동함 — 유저에겐 우연, 시스템엔 검증된 선택지. 구조: **하한선은 데이터로 보장(오늘의 앵커 1 — 장날·일몰·축제), 상한선은 우연에 개방(+N).** MVP 기준:

1. **접근 거리** — 현재 위치·진행 방향 기준 차로 10분 이내만 노출 (핵심 필터). 선택한 코스가 아니라 '지금 주변'이 기준 — 목적지가 바뀌어도 레이더는 그대로 작동
2. **발견 가치 점수** = 관광사진 보유 여부 + 감성 태그 매칭(취향 설정) + 데이터 완성도(영업시간·사진 있는 곳 우선)
3. **타이밍** — 식사 시간대엔 밥집 가중치, 일몰 1시간 전엔 뷰포인트 가중치. 노출 시점은 진출로 도달 시각 기준 역산
4. **중복 억제** — 같은 유형 연속 노출 방지, 30분당 알림 상한
5. **신뢰도 게이트** — 근접 알림(푸시/음성)에는 영업정보·사진이 검증된 스팟만 태움. 데이터가 얕은 스팟은 브라우징에서만 노출 (헛걸음 = 신뢰 붕괴, 페르소나 ③ 대응)

→ 제안서에 쓸 때 "관광데이터 기반 발견 점수"로 포장하면 API 활용 명분이 강해짐

## 5. 킬러 피처 — "각오 없는 발견" 3종 세트

무계획 여행 갈 '각오'를 요구하면 시장이 안 열림. 타깃은 무계획 여행자가 아니라 **이미 국도를 달릴 계획이 있는 사람**(캠핑길, 본가길, 바다길)이고, 그들의 계획에 "+1 우연"만 얹는다. 유저의 계산식: 리스크 10분 vs 리턴 = 아래 3종.

### ⑴ 자동 여행기 — 핵심 축 (MVP)
- 여행 종료 시 그날의 기록을 한 편의 에피소드로 자동 생성: 달린 국도·거리, 들른 발견, 스쳐간 곳, 허탕 친 곳까지
- **GPS 사진 자동 배치**: 여행 시간대 갤러리 사진을 위치·시각 메타데이터로 경로 위에 자동 정리 — 기록 노동 0으로 완성되는 사후관리
- **설계 의도: 실패의 서사화.** 풍향중에서 유재석이 지던 리스크를 앱이 대신 짐 — 문 닫힌 밥집도 여행기 안에선 에피소드가 되므로, 발견의 실패 비용이 심리적으로 0에 수렴. "각오" 문제의 근본 해법
- 공유 카드(세로형) 원탭 생성 → 인스타 공유 → 본 사람의 "이 길 나도 달려보기" 딥링크로 유입. **유저의 여행기 = 미니 풍향중 에피소드 = 자가 증식 마케팅 루프**
- 생성 자체는 이미 수집 중인 데이터(경로·정차·찜·사진 메타데이터)로 가능해 MVP 비용 낮음. 숏폼 영상 자동 생성은 2차

### ⑵ 장날 레이더 — "오늘만 있는 이유" (MVP)
- "12분 빠지면 **오늘이 마침 횡성 5일장**" — 언제든 볼 수 있는 정보는 안 누르지만, 오늘 지나치면 5일 뒤에 열리는 건 누름. 우연 → 놓치면 아까운 우연으로 격상
- 5일장은 끝자리 날짜(4·9일 등)로 구조화돼 있어 공공데이터로 구현 용이 + 밥·구경·특산물 원스톱이라 헛걸음 리스크 낮음 + "관광데이터로 5일장을 살린다"는 지역 활성화 서사까지 확보
- 동일 원리 확장: 일몰 뷰포인트("40분 뒤 일몰"), 계절 한정(개화·제철 수산물) — §4 타이밍 가중치의 전면화

### ⑶ 국도 수집 — "남는 것" (2차, 씨앗은 MVP)
- 지나온 국도가 지도에 색칠되고(7번 국도 86km 완주), 발견이 스탬프로 적립
- **"대한민국 국도 51선, 14,000km"** — 일반국도는 51개 노선(남북 27 · 동서 24), 총연장 약 1만 4천km(고속도로의 약 3배). 노선 수는 유한해 진행률이 보이고("51선 중 3선째"), 거리는 방대해 콘텐츠가 마르지 않음. 등산 앱 '100대 명산' 구조
- 41번·50번대 등 일부 노선은 북한 구간이라 실주행 불가 → 전체 보기에서 구분 표기. "1번 국도의 종점은 신의주" — 완주해도 끝나지 않는 길이라는 서사는 온보딩 감성 포인트로 활용
- MY-02 여행 기록이 이 피처의 그릇

## 9. 리스크 & 대응

1. **운전 중 조작** — 드라이브 모드는 오디오 안내 + 원탭 액션만, 상세 브라우징은 동승자 모드로 분리. 제안서에 안전 설계로 명시하면 플러스.
2. **데이터 빈 곳** — 국도변 소도시는 관광정보 데이터가 빈약할 수 있음. 코스 큐레이션을 데이터가 확인된 코스부터 시작 (전국 커버 주장 금지).
3. **위치 권한/배터리** — 경로 기록은 레이더 모드 중에만: 5~10초 간격 로깅 + 정차 감지 시 중지(차량 거치·충전 환경이라 배터리 부담 낮음). MVP는 iOS '앱 사용 중 허용'만으로 설계(백그라운드 '항상 허용'은 심사 리스크 — DR-06과 함께 2단계 옵트인). 경로는 기기 우선 저장, **여행기 공유 시 시작·끝 지점 ~300m 마스킹**(집 위치 노출 방지, 러닝 앱 홈존 패턴).
4. **내비 핸드오프 (기술 검증 완료)** — 카카오내비 SDK: 길안내 호출 + viaList로 경유지 전달 공식 지원 → **2단 핸드오프** 설계: ①출발 시 거점(목적지)+오늘의 앵커(경유지 1~2개) 전송 ②이동 중 "들르기"마다 스팟 단건 전송. 티맵은 공개 딥링크가 단일 목적지 수준이라 보조 지원. 코스 전체를 경유지로 박제하는 건 하지 않음(비내비 원칙 — 나머지 발견은 레이더가 실시간으로). 한계: 내비의 국도 경로 보장 불가 → 핸드오프 시 "무료도로 우선 설정" 안내 한 줄 + 고속도로 진입 시엔 발견이 조용해질 뿐 앱은 정상 작동(자연스러운 국도 복귀 넛지).

## 11. 유저 시나리오

### 시나리오 A — 혼자 캠핑 가는 32세 직장인 (솔로 모드)

> 목요일 밤, 평일 연차를 낸 준서는 양양 캠핑을 계획한다.

- **[전날 밤]** 홈(CO-01)에서 "44번 국도 고갯길" 코스를 열어본다. 경로 위 발견 포인트를 훑다가 계곡 뷰포인트 하나를 찜. **거점 정하기(CO-06)**에서 코스 종점 근처 캠핑장(고캠핑: 샤워실·화장실 확인됨)을 골라 외부 링크로 사이트 예약, 앱에 "거점 확정" 표시.
- **[금 09:30]** 출발하며 레이더 모드(DR-01) 켜고 폰은 거치대에. 혼자라 화면은 안 본다.
- **[10:40]** 오디오가 말한다. *"홍천 진출로 1분 전이에요. 오늘이 마침 홍천 5일장이에요."* (장날 레이더 — 전통시장표준데이터) 준서: **"응, 들를래."** (DR-04 음성 응답) → 카카오내비 딥링크로 전환.
- **[11:50]** 장터에서 메밀전 먹고 다시 출발. 이후 알림 두 개는 대답 안 함 → **자동 찜 적립**.
- **[14:00]** 주유소 정차. 정차 감지 → "아까 스쳐간 곳 2" 몰아보기 카드(DR-03). 하나는 다음에, 하나는 삭제.
- **[16:30]** 거점 캠핑장 도착. 밤에 **자동 여행기(MY-02)** 알림: *"44번 국도 138km, 들른 곳 1, 스쳐간 곳 2."* 인스타 공유 → 친구가 "이 길 나도 달려보기" 탭.

핵심 검증: 운전 중 화면 터치 0회. 거점이 확정돼 있어 장터에서 1시간을 써도 불안이 없음.

### 시나리오 B — 풍향중 보고 떠난 20대 커플 (동승자 모드)

> 토요일, 지수와 민호는 "우리도 국도로만 가보자"며 7번 국도 바다길을 고른다.

- **[출발 전]** 민호가 코스 상세(CO-02)에서 물회 골목 찜, 지수가 거점으로 강릉 쪽 게스트하우스 예약(CO-06).
- **[이동 중]** 운전은 민호, 지수는 **동승자 모드(DR-05)**로 앞쪽 스팟을 카드 스와이프. 지수가 등대 카페를 찜하자 운전석 화면에 "다음 정차지 제안"으로 뜸.
- **[12:10]** 근접 카드: *"어달마을 진출로 2분 전 — 들른 차들은 다음에 묵호등대로 갔어요."* (연관 관광지 데이터) 상의할 시간이 있어서(진출로 역산 타이밍) 여유 있게 결정 → 들르기.
- **[12:15]** 지수가 카드에서 네이버 후기 딥링크로 슬쩍 확인 — 앱은 막지 않는다(후기 정책).
- **[15:40]** 수다 떨다 뷰포인트 하나를 지나침. 앱은 되돌아가라고 하지 않는다. **"스쳐간 발견"에 조용히 적립(DR-03)** — 다음 여행의 씨앗.
- **[저녁]** 거점 도착, 여행기 생성. 제목: *"7번 국도에서 생긴 일".* 지나친 뷰포인트도 "놓친 곳 1"로 기록돼 다음 핑계가 된다.

핵심 검증: 결정은 항상 두 사람에게 시간이 있을 때 옴. 지나침이 실패가 아니라 콘텐츠가 됨.

### 시나리오 C — 숙소부터 예약하는 타입 (거점 역진입)

> 하윤은 J형 여행자다. 금요일에 이미 에어비앤비로 묵호의 독채를 예약해뒀다. 원래대로면 고속도로로 직행.

- **[출발 전]** P의 여행을 열고 코스는 건너뛴 채 **거점 설정(CO-06)**으로 직행. 검색창에 예약한 숙소 이름을 치고 핀 확정 — 앱은 어디서 예약했는지 묻지 않는다.
- 앱이 제안한다: *"고속도로로 2시간 10분. 근데 7번 국도로 가면 2시간 50분 — 대신 오늘이 북평 장날이고, 가는 길에 발견 9곳이 있어요."* 40분과 장날을 저울질하다 국도를 받는다.
- **[이동 중]** 거점이 기준점이 된 레이더: *"거점까지 남은 길에 들를 곳 2."* 장날 카드에 핸들을 꺾고, 일몰 카드는 ✕ — 스쳐간 발견으로 적립.
- **[저녁]** 예약해둔 독채 도착. 여행기 생성: *"고속도로였다면 없었을 하루."* 말미에 한 줄 — *"묵호가 좋았다면, 하루 더?"* 탭하면 주변 숙박 정보와 외부 링크만 조용히 뜬다.

핵심 검증: 숙소를 먼저 정하는 유저도 입력 하나로 수용 — 우리는 숙소를 팔지 않고, **빠른 길 대신 재밌는 길로 갈 이유**를 판다.
