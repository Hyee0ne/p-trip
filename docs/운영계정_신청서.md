# data.go.kr 운영계정 신청 — 작성 내용

> ⚠ 신청 양식이 로그인 뒤에 있어 **실제 필드는 확인하지 못했다.** 아래는 그 신청서가
> 통상 묻는 항목에 맞춰 쓴 내용이다. 필드 이름이 다르면 해당 칸에 맞게 옮겨 넣으면 된다.
> 숫자는 2026-08-30 기준 실측·추정이며 근거를 같이 적었다.

---

## 1. 서비스 개요

**서비스명**: P의 여행

**한 줄 소개**
국도 위의 우연한 발견을 설계하는 '발견 레이더' 모바일 앱.

**서비스 형태**: iOS 모바일 애플리케이션 (Flutter). 출시 준비 중.

**해결하려는 문제**
고속도로는 빠르지만 아무것도 남지 않는다. 국도에는 오늘만 서는 장, 40분 뒤의 일몰,
이름 없는 물회 골목이 있는데 **지나치고 나서야 알게 된다.**
이 앱은 달리는 중에 "지금 앞쪽 3~7분 거리에 무엇이 있는지"를 알려준다.

**대상 이용자**
주말이 소중한 사람들. 시간을 통째로 비울 수 없어서 계획 없이 떠나기는 어렵고,
그렇다고 정해진 코스만 따라가면 재미가 없는 사람.

---

## 2. 활용 목적

관광 정보를 **자체 DB에 배치로 적재**하여, 사용자의 현재 위치·진행 방향·시각을 기준으로
주변 관광지를 추천한다.

**⚠ 런타임에 오픈API를 직접 호출하지 않는다.** 앱은 자체 DB(Supabase/PostgreSQL)만 조회한다.
수집은 서버 측 배치 스크립트가 주기적으로 수행한다. 그 이유는 셋이다.

1. **호출량 절감** — 사용자 수가 늘어도 API 호출량이 늘지 않는다
2. **응답 지연 제거** — 주행 중 사용하는 앱이라 지연이 안전 문제로 직결된다
3. **인증키 보호** — 인증키가 앱 번들에 포함되지 않는다

**공간 연산이 필요해 자체 적재가 불가피하다.** 수집한 관광지를 국토교통부 도로중심선
기반의 국도 51선 선형에 PostGIS로 대조하여, 국도에서 도보/차량 10분 이내인 것만 남기고
진출 지점과 우회 시간을 미리 계산한다. 이 연산은 오픈API 응답만으로는 수행할 수 없다.

## 3. 활용 신청 오픈API

| 제공기관 | 서비스명 | 사용 오퍼레이션 | 용도 |
|---|---|---|---|
| 한국관광공사 | 국문 관광정보 서비스_GW | `areaBasedList2`, `detailIntro2`, `detailCommon2` | 관광지 기본정보·영업정보·개요 |
| 한국관광공사 | 관광지 연관 관광지 정보 서비스 | `areaBasedList1` | 방문 흐름 변화 파악 |
| 한국천문연구원 | 출몰시각 정보 | `getLCRiseSetInfo` | 일몰·천문박명 (일몰 시각 안내) |
| 한국천문연구원 | 천문우주 지식정보 (천문현상) | `getAstroEventInfo` | 유성우·월식 등 그날의 천문현상 |

※ 전국전통시장표준데이터는 오픈API가 아닌 파일(CSV) 제공이라 신청 대상이 아니다.

## 4. 일일 트래픽 신청량

**신청량: 일 10,000건** (오퍼레이션 합산 기준)

### 산정 근거

**초기 전국 적재 (1회성)**

| 항목 | 호출 수 | 근거 |
|---|---|---|
| 목록 조회 | 약 500 | 시도 17개 × 페이지(100건 단위) |
| 상세(영업정보) | 약 100,000 | 국도 회랑 10km 안 관광지 1건당 1콜 |
| 개요 | 약 20,000 | 신뢰도 기준 통과분만 선별 호출 |
| 연관 관광지 | 약 3,000 | 지역 단위 2개 시점 |
| 출몰시각 | 약 8,000 | 0.1도 격자 × 14일 |
| 천문현상 | 약 20 | 월 단위 |

초기 적재는 **약 13만 콜**이며, 일 10,000건 기준으로 **약 2주에 걸쳐 나눠 수집**한다.
수집 스크립트는 중단·재개를 전제로 작성되어 있어 일일 한도에 도달하면 멈추고
다음 날 이어받는다.

**정상 운영 시 (초기 적재 이후)**

| 항목 | 호출 수 |
|---|---|
| 신규·변경 관광지 갱신 (월 1회) | 약 10,000 / 월 |
| 출몰시각 (일 단위 캐시) | 약 300 / 일 |
| 연관 관광지 (분기 1회) | 약 3,000 / 분기 |

즉 **정상 운영 시 일 평균 500건 내외**이고, 신청량 10,000건은 초기 적재와
갱신 배치가 겹치는 날을 감안한 값이다.

### 호출 절감을 위해 이미 적용한 것

- **회랑 사전 필터** — 목록으로 받은 좌표를 국도 51선 선형과 대조해 회랑 밖은
  상세를 아예 호출하지 않는다. 상세는 1건당 1콜이라 이 필터가 호출량을 크게 줄인다
- **선별 호출** — 개요(`detailCommon2`)는 신뢰도 기준을 통과한 관광지에만 호출한다
- **목록 캐시** — 수집 재개 시 목록을 다시 받지 않는다
- **호출 간격 제어** — 동시 4건 + 250ms 간격으로 초당 요청 수 제한을 준수한다

## 5. 시스템 구성

```
[배치 수집기 (Node.js)]  ──(오픈API)──▶  data.go.kr
        │
        │ 적재
        ▼
[Supabase / PostgreSQL + PostGIS]
        │  · 관광지, 국도 51선 선형, 장날, 일출·일몰, 천문현상
        │  · 국도 대조·진출점·우회시간 사전 계산
        │
        │ 조회 (앱은 여기만 본다)
        ▼
[iOS 앱 (Flutter)]
```

**인증키 보관**: 수집기 서버의 환경변수. 앱 번들과 저장소에 포함하지 않는다.

## 6. 개인정보 처리

- **회원가입·로그인이 없다.** 계정을 만들지 않는다
- 찜·여행 기록은 **이용자 기기 안에만** 저장한다. 서버로 보내지 않는다
- 위치 정보는 **주변 관광지 조회에만 즉시 사용**하고 서버에 저장하지 않는다
- 오픈API로 받은 데이터에는 개인정보가 포함되지 않는다
