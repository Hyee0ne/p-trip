**유리한 사실 (코드로 확인함)**
- 좌표는 **언제나 POST 본문**이다. 우리 쪽 URL에 실리는 곳이 하나도 없다 →
  게이트웨이 액세스 로그(메서드·경로·상태·IP)에 좌표가 안 남는다
- Edge Function 두 개에 **`console.log` 가 하나도 없다** → 함수 로그에 좌표가 안 남는다
- 가장 잦은 흐름(레이더)은 이미 **1.1km 격자**다. 원래는 provider 캐시 때문에 넣은 건데
  결과적으로 정확한 좌표가 안 나간다
- 좌표를 받는 DB 함수는 전부 `STABLE` — 구조적으로 저장이 불가능하다

**남은 구멍**
- `nearby_routes` · `route_path_ahead` 가 **원본 좌표**를 보낸다
- `search_places` 가 좌표를 **카카오 URL 쿼리(`x`,`y`)** 로 넘긴다 — 외부 액세스 로그에 남는 형태

## 해야 할 일

### ① 클라우드 로그 확인 (담당자가 지목한 Q3) — **확인 완료 (2026-09-07)**

**ⓐ 스키마** — Supabase 공식 문서. `edge_logs` 는 요청 헤더를 **허용목록**으로만 기록한다:
`accept · cf-connecting-ip · cf-ipcountry · host · user-agent · x-forwarded-proto ·
referer · content-length · x-real-ip · x-client-info · x-forwarded-user-agent · range · prefer`
→ **요청 본문 필드가 아예 없다.** 우리 좌표는 전부 POST 본문이다.
→ 단 **IP 는 남는다** (`cf-connecting-ip`, `x-real-ip`).

**ⓑ 실제 로그 화면** — 대시보드에서 눈으로 확인했다.
```
POST | 200 | .../rest/v1/rpc/sun_moon_today                                   ← 경로만
GET  | 200 | .../rest/v1/sun_moon?select=locdate&order=locdate.desc&limit=1   ← 쿼리스트링 통째로
```
GET 은 쿼리스트링이 그대로 찍히는데 **POST RPC 는 경로만 찍힌다.** 스키마대로다.
같은 시각 `Error 5xx = 0` · `Warning 4xx = 0`, Postgres 로그는 `checkpoint` 메시지뿐이었다
— 쿼리문도 파라미터도 없다.

**ⓒ 보관 기간** — 공식 가격표. 우리는 **Free 플랜 = 1일**.
(Pro 7일 · Team 28일 · Enterprise 90일)
→ 설령 어딘가에 좌표가 실려도 **24시간 뒤 사라진다.** '보유하지 않는다'의 근거다.

⚠ 유일하게 남는 이론적 구멍: 쿼리가 **실패하면** `postgres_logs.event_message` 에
  문장과 파라미터가 실릴 수 있다. 다만 거기엔 앱 사용자 IP 가 없고(풀러 연결),
  Free 플랜이라 하루면 사라지며, 확인 시점에 5xx 가 0이었다.
  → ②(격자화)를 하면 이 경우에도 찍히는 건 **한 사람의 위치가 아니라 격자 한 칸**이 된다.

### ② 좌표 격자화 — **완료 (2026-09-07)**

서버로 나가는 좌표를 **전부 0.01도(위도 1.11km · 경도 0.88km) 격자로 뭉갠다.**
저장소 한 곳(`supabase_discover_repository._cell`)을 거치게 해서 구조적으로 새지 않게 했다.

| 흐름 | 전 | 후 |
|---|---|---|
| `discover_ahead` (레이더) | 0.01° 격자 | 그대로 (이미 뭉개져 있었다) |
| `discover_ahead` (지역 판정) | 0.25° 격자 | 그대로 |
| `sun_moon_today` | 0.1° 격자 | 그대로 |
| `nearby_routes` | ⚠ 원본 | **0.01° 격자** |
| `route_path_ahead` | ⚠ 원본 | **0.01° 격자** |
| `compare_routes` → 카카오모빌리티 | ⚠ 원본 | **0.01° 격자** |
| `search_places` → 카카오 | ⚠ 원본 | **0.01° 격자** |

**왜 1.1km 인가** — 이 앱이 좌표를 쓰는 용도가 전부 그보다 굵다.
레이더 반경 5km · 국도 탐색 30km · 앞길 선형 120km · 장소 검색은 근접 정렬 힌트다.

**왜 이게 답변에 쓸모 있나** — 담당자가 지목한 유일한 구멍이 '쿼리 실패 시 인프라 로그에
파라미터가 실릴 수 있다' 였다. 로그 설정은 우리가 못 바꾼다. **보내는 값이 우리가 쥔
유일한 손잡이다.** 이제 최악의 경우에도 로그에 남는 건 한 사람의 위치가 아니라 격자 한 칸이다.

⚠ **소스를 읽는 테스트로 잠갔다** (`app/test/coordinate_grid_test.dart`, 4건).
  새 쿼리를 추가하면서 `_cell()` 을 빼먹는 게 이 방어가 무너지는 유일한 경로인데
  화면도 린트도 그걸 못 잡는다. 좌표를 URL 쿼리스트링에 싣는 것도 함께 막는다 —
  게이트웨이 로그는 URL 은 통째로 남기고 본문은 안 남기기 때문이다.

### ③ 근본 구조 (1~2일) — 담당자가 권한 (나)
지역 단위 데이터를 미리 내려받아 좌표를 아예 안 보낸다.
⚠ **전국 스팟이 3,341건(약 1MB)이라 통째로 내려받을 수 있다.** 지역을 나눌 필요도 없다.
`sun_moon` 도 41칸 × 30일 = 1,230행이라 같이 내려받으면 된다.
그러면 레이더·일몰·국도 판정이 전부 기기 안에서 끝나고, 남는 건 사용자가 직접 누르는
거점 검색(카카오)뿐이다. **오프라인 주행이 덤으로 따라온다** — 국도엔 음영지역이 많다.

### ④ 마감(2026-09-21) 기준 판단 — **①②까지 하고 출시 유지**

답변이 "신고 대상이 아닐 수 있다" 쪽이고, ①에서 좌표가 로그에 안 남는 것을 확인했으며,
②로 보내는 값까지 뭉갰다. **출시를 멈출 이유가 없다.** ③은 공모전 이후로 미룬다.

**지금 사실대로 말할 수 있는 것**
- 회원가입·로그인이 없다. 회원 ID·계정·기기 식별자를 좌표와 함께 보내지 않는다
- 좌표는 **0.01도 격자로 뭉개서** 보낸다. 정확한 GPS 좌표는 기기를 떠나지 않는다
- 좌표를 받는 DB 함수는 전부 `STABLE` — 구조적으로 저장이 불가능하다

- 인프라 로그 보관은 **1일**(Free 플랜)이다
- 주행 경로·방문 기록·찜은 전부 휴대폰 안에만 있다 (로그인이 없어 올릴 데가 없다)

⚠ Q5(신고 완료 전 운영 가능 여부)는 담당자가 **법률 전문가 확인 사항**으로 남겼다.

   - 위도·경도를 소수점 둘째 자리에서 반올림합니다 (0.01도 = 약 1.1km × 0.9km).
   - 기기의 정확한 GPS 좌표는 서버로 전송되지 않습니다.
   - 서버에 새 요청을 추가할 때 이 규칙을 빠뜨릴 수 없도록 소스 검사 테스트로 잠갔습니다.

2) 외부 제3자로 좌표가 나가는 경로를 전부 없앴습니다.
   - 이전에는 장소 검색과 경로 비교를 위해 카카오 API로 좌표를 전달했습니다.
   - 해당 기능을 삭제해 이제 좌표는 저희 서버(Supabase) 하나로만 전송됩니다.

■ 그대로인 것 (지난 문의와 동일)

- 회원가입·로그인이 없습니다. 회원 ID·계정·기기 식별자·광고 식별자를 좌표와 함께
  보내지 않습니다.
- 좌표를 받는 서버 함수는 전부 읽기 전용(STABLE)으로 선언되어 DB에 저장할 수 없습니다.
- 주행 경로·방문 기록·저장한 장소는 휴대폰 안에만 있습니다. 서버로 올라가지 않습니다.

■ 클라우드 로그 (지난 답변에서 확인하라고 하신 부분) — 확인했습니다

- 좌표는 항상 HTTP POST 본문으로만 전송됩니다. URL 쿼리스트링에 실리는 경우가 없습니다.
- Supabase의 API 게이트웨이 로그는 요청 헤더만(허용목록 방식) 기록하고 요청 본문 필드가
  없습니다. 실제 로그 화면에서 POST 요청은 경로만 기록되는 것을 확인했습니다.
- 서버 함수 코드에 좌표를 출력하는 로그문이 없습니다.
- 로그 보관 기간은 1일입니다(Free 플랜).
- 게이트웨이 로그에 접속 IP는 남습니다. 다만 같은 줄에 좌표가 없으므로 IP와 좌표가
  결합되는 기록은 생기지 않습니다.

■ 정리하면, 서버가 받는 것은
  "익명의 요청이, 약 1km 격자 한 칸을 가리키며, 그 주변 관광지를 묻는다"
  이며 이 요청은 저장되지 않고, 로그에도 남지 않으며, 외부로 나가지 않습니다.

■ 질문드립니다

    식별자가 없고, 정확한 좌표가 아니며, 사업자가 결합할 다른 정보를 보유하지 않는
    구조입니다.

Q2. Q1이 "해당하지 않는다"면, 저희 서비스는 위치기반서비스사업 신고 대상이 아닌 것으로

    그 부분을 바꾸겠습니다. (예: 격자 크기, 전송 자체, 로그의 IP 등)

## 이 문의로 기대하는 것

담당자가 지난 번에 "가능성이 있다"까지만 말한 건 우리 설명이 추상적이어서였다.
