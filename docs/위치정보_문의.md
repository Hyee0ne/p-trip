## 1. 서비스 개요

- 앱 이름: **P의여행:국도편** (App Store 출시, 앱 ID 6806749553)
- 하는 일: 국도를 주행하는 사용자에게 **현재 위치 반경 5km 안**의 관광지·음식점 등을
  알려주는 앱. 목적지를 정하지 않고 길만 고르는 방식.
- 데이터 출처: 한국관광공사 국문관광정보(TourAPI) 등 공공데이터
- 개인/1인 개발, 2026 관광데이터 활용 공모전 출품작이자 정식 출시작

## 2. 확인된 사실 (코드 기준)

### 서버로 **전송되는** 것

앱이 서버(Supabase, PostgreSQL)의 조회 함수를 호출할 때 **위경도를 파라미터로 보낸다.**

| 호출 | 시점 | 보내는 값 |
|---|---|---|
| `discover_ahead` | 주행 중 반복 | 위도·경도·진행방향·반경 |
| `nearby_routes` | 홈 진입 시 | 위도·경도 |
| `sun_moon_today` | 일몰 계산 | 위도·경도(약 11km 격자로 뭉갬) |
| `route_path_ahead` | 노선 조회 | 위도·경도 |
| `search_places` | 검색 시 | 위도·경도 |

### 서버로 **전송되지 않는** 것

- **로그인·회원가입이 없다.** 계정 개념 자체가 없다 (인증 호출 0건)
- **기기 식별자·광고 식별자·사용자 ID를 보내지 않는다** (코드 전수 확인)
- **주행 궤적·방문 기록·찜 목록은 단말기 안에만** 저장된다. 서버로 올리지 않는다

### 서버에서의 처리

- 위경도를 받는 함수 5개는 전부 **`STABLE`** 로 선언돼 있다.
  PostgreSQL에서 `STABLE` 함수는 **데이터베이스를 변경할 수 없다.**
- 마이그레이션 전체에 위경도를 저장하는 `INSERT`/`UPDATE` 문이 **없다.**
- 즉 좌표는 **반경 조회 조건으로만 쓰이고 즉시 버려진다.**
- ⚠ 다만 서버 인프라(Supabase) 의 **요청 로그**에는 남을 수 있다. 이 부분은 확인 중.

## 3. 질문

**Q1.** 로그인이 없고 기기·사용자 식별자를 함께 보내지 않는 상태에서,
**위경도만** 서버로 전송해 조회 조건으로 쓰고 저장하지 않는 경우
이를 「개인위치정보」로 보아 **위치기반서비스사업자 신고 대상**이 되는지?

**Q2.** 가이드라인에 「서버 DB 저장 여부와 무관하게 전송하는 자체만으로도 대상」이라고
되어 있는데, 이때의 전송은 **특정 개인과 결부될 수 있는 경우**를 전제하는지,
아니면 식별자 없는 좌표도 포함하는지?

**Q3.** 인프라 제공자(Supabase)의 **요청 로그에 좌표가 남는 경우**,
사업자가 그 로그를 조회·활용하지 않더라도 「전송·활용」에 해당하는지?

**Q4.** 신고 대상이 아니게 하려면 아래 중 어느 수준이면 충분한지?
1. 좌표를 **격자(예: 25km)로 뭉개서** 전송하고, 정밀 판정은 단말기에서 수행
2. 지역 단위 데이터를 **미리 내려받아** 단말기에서만 반경 계산 (좌표를 아예 전송하지 않음)

**Q5.** 이미 App Store에 출시된 상태다. 신고 대상이라면
**신고 완료 전까지 서비스를 중단해야 하는지**, 아니면 신고 절차를 진행하면서
운영할 수 있는지?
