# 출시 절차 — Xcode · App Store Connect

> ⚠ 여기 있는 대부분은 **웹과 Xcode에서 직접 하셔야 합니다.** 자동화할 수 없습니다.
> 코드·문서 쪽에서 준비된 것은 각 단계에 표시했습니다.

## 0. 먼저 확인 — Apple Developer Program 등록 여부

**등록이 안 되어 있으면 아래 전부가 막힙니다.**

- https://developer.apple.com/account → 멤버십 상태 확인
- 미등록이면: Apple Developer Program 가입 (개인 기준 **연 $99**, 승인에 1~2일)

⚠ **지금 실기기에 설치되는 것은 등록 여부와 무관합니다.** 무료 개인 인증서로도
  7일짜리 설치가 됩니다. "잘 깔리니까 등록된 것"이라고 볼 수 없습니다.

확인법: Xcode → Settings → Accounts → 계정 선택 → 팀 이름 옆에 역할이
`Agent`/`Admin`이면 유료 등록, `Personal Team`이면 미등록입니다.

## 3. Xcode에서 확인할 것

Xcode로 `app/ios/Runner.xcworkspace`를 엽니다.

| 위치 | 확인 |
|---|---|
| Runner → Signing & Capabilities | Team이 **유료 팀**인지 (Personal Team이면 업로드 불가) |
| 같은 화면 | `Automatically manage signing` 체크 |
| General → Identity | Display Name `P의 여행`, Bundle ID 일치 |

⚠ **Signing & Capabilities에 Background Modes를 추가할 필요는 없습니다.**
  Xcode가 그 UI로 하는 일이 결국 Info.plist에 키를 쓰는 것이고, 이미 있습니다.
  중복해서 추가하면 plist에 항목이 두 번 들어갈 수 있습니다.

## 4. 버전

현재 `app/pubspec.yaml`의 `version: 0.1.0+1`.

첫 출시라면 **`1.0.0+1`**로 올리는 것이 관례입니다.
- `1.0.0` = 스토어에 보이는 버전
- `+1` = 빌드 번호. **업로드할 때마다 반드시 올려야 합니다** (같은 번호는 거부됩니다)

## 5. 업로드 — 실제로 통한 경로 (2026-08-30 1.0.0(1) 업로드 완료)

배포 인증서 개인키가 이 맥에 없어도 된다. **App Store Connect API 키**를 쓰면
Xcode가 없는 인증서를 알아서 만들고 개인키까지 로컬에 생성한다.

### 5-1. 자격증명 (한 번만)

```
~/.appstoreconnect/private_keys/AuthKey_7U29A76MBG.p8   # chmod 600, 디렉터리 700
Issuer ID: ea714c32-bf27-4e6f-b4cd-cadb3b7a3908
Team ID:   2Q5557H9T4
```

`~/.appstoreconnect/private_keys/`는 `xcodebuild`·`altool`이 **자동으로 찾는 표준 경로**다.
⚠ `.p8`·`.p12`·`.cer`는 `.gitignore`에 있다. 저장소가 공개라 반드시 확인하고 커밋할 것.

### 5-2. 빌드 → 아카이브 → IPA

```bash
cd app
flutter build ipa --release --dart-define-from-file=dart_defines.json
```

`flutter build ipa`가 서명에서 막히면 아카이브만 만들고 내보내기는 수동으로 한다:

```bash
xcodebuild -exportArchive \
  -archivePath build/ios/archive/Runner.xcarchive \
  -exportOptionsPlist ExportOptions.plist \
  -exportPath build/ios/ipa \
  -allowProvisioningUpdates \
  -authenticationKeyPath ~/.appstoreconnect/private_keys/AuthKey_7U29A76MBG.p8 \
  -authenticationKeyID 7U29A76MBG \
  -authenticationKeyIssuerID ea714c32-bf27-4e6f-b4cd-cadb3b7a3908
```

`ExportOptions.plist`는 `method=app-store-connect`, `teamID=2Q5557H9T4`,
`signingStyle=automatic`, `destination=export`.

### 5-3. 검증 → 업로드

```bash
xcrun altool --validate-app -f build/ios/ipa/p_trip.ipa -t ios \
  --apiKey 7U29A76MBG --apiIssuer ea714c32-bf27-4e6f-b4cd-cadb3b7a3908
xcrun altool --upload-app   -f build/ios/ipa/p_trip.ipa -t ios \
  --apiKey 7U29A76MBG --apiIssuer ea714c32-bf27-4e6f-b4cd-cadb3b7a3908
```

**검증을 먼저 돌린다.** 아이콘·plist·권한 오류를 빌드 번호 소모 전에 잡는다.

### 5-4. 올리기 전에 바이너리를 직접 확인한다

⚠ **dart-define은 조용히 빠진다.** zsh는 따옴표 없는 `$VAR`를 단어 분리하지 않아서
전에 `SUPABASE_URL` 하나만 들어가고 앱이 픽스처로 돈 적이 있다.
`--dart-define-from-file`을 쓰되, 아카이브 바이너리를 열어 눈으로 확인한다:

```bash
B=build/ios/archive/Runner.xcarchive/Products/Applications/Runner.app/Frameworks/App.framework/App
python3 -c "
import json
d=json.load(open('dart_defines.json'))
raw=open('$B','rb').read()
for k,v in d.items():
    if len(str(v))>=6: print(('OK  ' if str(v).encode() in raw else 'MISS'), k)
print('DEMO_BUILD:', raw.count(b'DEMO_BUILD'), '(0이어야 한다)')
# 한글 문구는 UTF-16 으로 찾는다 (아래 참고)
for s in ['데이터 출처','한국관광공사']:
    print(('OK  ' if s.encode('utf-16-le') in raw else 'MISS'), s)
"
```

⚠ **Dart AOT는 한글 문자열을 UTF-16으로 저장한다.** `strings`는 ASCII만 뽑아서
  한글이 하나도 안 잡히고, 그걸 '문구가 빠졌다'로 오해하기 쉽다.
  ASCII 키(`SUPABASE_URL` 등)는 그냥 찾히지만 한글은 `s.encode('utf-16-le')`로 찾아야 한다.

⚠ **출시 빌드에는 `DEMO_BUILD`를 넣지 않는다.** 넣으면 설정에 '데모 모드'(가짜 주행)가 보인다.
실기기 테스트 빌드에만 넣는다.

### 알려진 경고

```
90068  MinimumOSVersion 13.0 — 2027년 봄부터 15.0 이상만 받는다
```

## 5-5. 스토어 정보는 API로 채운다 (2026-08-30 완료)

손으로 옮겨 적지 않는다. `docs/앱스토어_등록정보.md`가 단일 소스고
`tools/asc/`가 그 문서를 읽어 넣는다.

```bash
python3 tools/asc/asc_status.py   # 무엇이 비어 있는지 (읽기 전용)
python3 tools/asc/shots.py        # 스크린샷 업로드
```

⚠ **버전 레코드와 빌드의 버전 문자열이 같아야 빌드가 붙는다.**
  ASC 기본값은 `1.0`인데 우리 빌드는 `1.0.0`이었다. `1.0.0`으로 고쳤다.

⚠ **사전서명 업로드 URL에 `Authorization`을 붙이면 400.**
  `uploadOperations`의 URL은 ASC 토큰을 받지 않는다.

### 콘텐츠 권한 (Content Rights)

`apps/{id}` 의 `contentRightsDeclaration` = **`USES_THIRD_PARTY_CONTENT`** (2026-08-30 설정).

「사용 안 함」으로 답할 수 없다 — 관광공사 사진을 원본 그대로 띄우고(워터마크가 보인다),
개요 텍스트를 저장해 보여주고, 카카오 지도 타일을 렌더링한다.
스크린샷 3·5번에 워터마크가 찍혀 있어 심사자가 바로 본다.

⚠ 그래서 **앱 안에 「데이터 출처」가 있어야 한다** (설정 맨 아래, SCREENS.md MY-01/03).
  공공누리는 유형과 무관하게 출처표시가 의무고, 스토어 설명이 아니라
  콘텐츠를 쓰는 화면에서 밝혀야 한다.

### API로 안 되는 것 — 웹에서만

**앱 개인정보(App Privacy) 설문.** `appDataUsages` 계열은 전부 404다.
App Store Connect → 앱 → **앱 개인정보** 에서 직접 답한다. 답은 이미 정해져 있다
(`docs/site/privacy.md`가 근거):

| 항목 | 답 |
|---|---|
| 위치 (정확한 위치) | **수집함** · 목적 「앱 기능」 · **사용자에 연결 안 함** · **추적에 사용 안 함** |
| 사진 | **수집 안 함** — 기기를 벗어나지 않는다 |
| 식별자·연락처·사용 데이터·진단 | **수집 안 함** — 로그인 없음, 광고 없음, 분석 SDK 없음 |

⚠ 「추적」에 예로 답하면 ATT 권한 요청 화면이 없다는 이유로 반려된다. 우리는 추적하지 않는다.

### 개인정보 보호 (App Privacy) 답변

App Store Connect가 묻는 항목에 대한 **사실 그대로의 답**:

| 질문 | 답 |
|---|---|
| 데이터를 수집하나요? | **위치만**. 그 외 없음 |
| 위치 — 정확한 위치 | 예. **앱 기능**용으로만. 추적 안 함, 사용자와 연결 안 함 |

| 사용 데이터·진단 | 아니오 (분석 SDK 없음) |
| 사진 | **수집하지 않음** — 기기에서 읽기만 하고 서버로 안 보냄 |
| 추적(Tracking)에 쓰나요? | **아니오**. IDFA 없음, ATT 프롬프트 없음 |

**2. 심사자가 한국 밖에 있으면 앱이 비어 보입니다**
이 앱은 대한민국 국도가 전제입니다. **심사 메모에 좌표를 반드시 적습니다**
(37.5245, 129.1143 — 동해, 7번 국도 위). 안 적으면 "동작하지 않는다"로 반려될 수 있습니다.
